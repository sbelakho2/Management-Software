# 1.2 Database Schema Design

## Overview

Sensei OS uses PostgreSQL 16 with SQLAlchemy 2.0 ORM and Alembic for migrations. The schema is designed around lean manufacturing principles, supporting CRM, quality management, shop floor control, and continuous improvement workflows.

## Database Configuration

- **Database**: PostgreSQL 16 with asyncpg driver
- **Extensions**: `pg_trgm` for trigram text search
- **ORM**: SQLAlchemy 2.0 with async support
- **Migrations**: Alembic with async support

## Base Model Architecture

All models inherit from a common Base class providing:

\`\`\`python
class Base(DeclarativeBase):
    id: Mapped[UUID] = mapped_column(
        UUID(as_uuid=True),
        primary_key=True,
        default=uuid.uuid4,
    )
\`\`\`

### Common Mixins

| Mixin | Fields | Purpose |
|-------|--------|---------|
| TimestampMixin | created_at, updated_at | Automatic timestamp tracking |
| AuditMixin | created_by_id, updated_by_id, owner_id | User audit trail |
| SoftDeleteMixin | deleted_at, deleted_by_id | Soft delete support |

## Indexes Strategy

### Single-Column Indexes
- All foreign keys
- Status/state columns for filtering
- Date columns for range queries
- Unique identifiers (account_number, rfq_number, etc.)

### Composite Indexes
- Status + date combinations
- Parent ID + order (for sorted children)
- Type + status combinations

### Partial Indexes
- Active records only (where deleted_at IS NULL)
- Open/in-progress items

### Specialized Indexes
- GIN trigram for text search (ix_accounts_name_search)
- Expression indexes on lowercased emails

## Constraints

### Check Constraints
- Positive quantities and amounts
- Percentage ranges (0-100)
- Date validations (end >= start)
- Score ranges

### Unique Constraints
- Business identifiers (account_number, rfq_number, etc.)
- Composite uniqueness (work_order + operation sequence)

### Foreign Key Behaviors
- ON DELETE CASCADE for child records
- ON DELETE SET NULL for optional references
- use_alter=True for circular dependencies

## Performance Considerations

1. **UUID Primary Keys**: Used for distribution-friendly IDs on core entities
2. **Integer Primary Keys**: Used for high-volume Phase 3 tables for performance
3. **Table Partitioning**: Range partitioning by `created_at` for high-growth tables (`audit_logs`, `condition_readings`) to maintain query performance and simplify data retention.
4. **JSONB Fields**: Used for flexible metadata (team_members, tags, custom_fields)
5. **Soft Deletes**: Enabled for data retention compliance
6. **Async Operations**: Full async support via asyncpg driver
